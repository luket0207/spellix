Feature-004: Prevent rivers and streams from forming loops

Status

* done

Goal

* Revisit river and stream generation.
* Prevent rivers and streams from ever forming loops.
* Ensure each river or stream behaves like a single ordered path.
* A river or stream square should only touch the water square directly before it or directly after it in that same path order.

Scope

* Update river and stream generation logic.
* Apply this rule to both rivers and streams.
* A generated river or stream should be treated as an ordered path.
* Each water square in the path should know, or be checkable against, its position in that path.
* Water path squares must not form loops.
* Water path squares must not branch.
* Water path squares must not reconnect to earlier parts of the same path.
* Water path squares must not touch unrelated river or stream paths.
* Keep existing river and stream environment rendering.
* Keep existing river and stream animation.
* Keep existing river and stream colour styling.
* Keep existing river and stream length rules unless a path must be retried because it would create a loop.

Water Touching Rule

* For any river or stream path, a water square may only touch:

  * the previous square in that same path.
  * the next square in that same path.
* A water square must not touch:

  * any earlier square in the same path that is not the direct previous square.
  * any later square in the same path that is not the direct next square.
  * any water square from another river path.
  * any water square from another stream path.
  * any water square from a different water cluster.
* This means water paths should behave like clean, one-square-wide lines.

Path Validity Rules

* Rivers and streams must not form loops.
* Rivers and streams must not form rings.
* Rivers and streams must not form closed paths.
* Rivers and streams must not self-intersect.
* Rivers and streams must not double back into themselves.
* Rivers and streams must not create branches or junctions.
* Rivers and streams must not create 2x2 blocks of water.
* Rivers and streams must remain one square wide.
* Each path should have two path ends unless the path length is 1.
* A middle square in a path should normally touch exactly two water squares:

  * the square before it.
  * the square after it.
* An end square in a path should normally touch exactly one water square:

  * either the square after it or the square before it.
* A newly placed water square should be rejected if it touches any water square other than the direct previous square in the path being generated.

Generation Requirement

* When generating a river or stream, track the ordered list of squares in that path.
* Before placing a candidate next square, check all neighbouring water squares.
* The candidate square is only valid if the only water square it touches is the current end of the same path.
* The candidate square must not touch any other water square.
* The generator should not rely only on checking the candidate square.
* It should also ensure the new placement does not cause existing nearby water squares to become invalid.
* After a river or stream path is generated, validate the finished path.
* If the finished path contains a loop, branch, invalid touch, or 2x2 water block, discard that path and retry.
* Use a reasonable retry limit.
* Do not enter an infinite loop if valid water placement is difficult.
* If a valid path cannot be generated, fail safely by skipping that path or using the smallest existing safe fallback.

Neighbour Checking Requirement

* Check orthogonal neighbours when determining whether water squares touch.
* Orthogonal neighbours are:

  * above.
  * below.
  * left.
  * right.
* If the current visual rendering makes diagonal water look connected, also avoid diagonal contact where practical.
* The core required rule is that no water square should edge-touch another water square unless it is directly before or after it in the same ordered path.

Expected Behaviour

* Rivers no longer generate as loops.
* Streams no longer generate as loops.
* Rivers no longer reconnect to themselves.
* Streams no longer reconnect to themselves.
* Rivers and streams do not form circular or ring-like shapes.
* Rivers and streams do not branch.
* Rivers and streams do not form 2x2 water blocks.
* A river square only touches the river square before or after it in the same river path.
* A stream square only touches the stream square before or after it in the same stream path.
* Separate water paths do not touch each other.
* Existing river and stream visuals still render correctly.
* Existing board generation still completes safely.

Out Of Scope

* No changes to river or stream colours.
* No changes to river or stream animation.
* No changes to river or stream image assets.
* No changes to non-water environment generation.
* No changes to Start Area rules.
* No changes to Elite Battle areas.
* No changes to Boss Battle area.
* No changes to generated feature count.
* No changes to generated feature spacing.
* No changes to player placement.
* No changes to movement rules.
* No changes to dice logic.
* No changes to spells.
* No changes to debug menu.
* No save/load functionality.
* No persistence.
* No unrelated board generation changes.

* “The ones directly before or after it in the order” means the previous and next squares in the generated river or stream path array.
* Rivers and streams are generated as one-square-wide paths.
* The board uses orthogonal movement and orthogonal water adjacency for path connection.
* Existing water generation can be retried if a candidate path creates invalid touching.
* It is acceptable to skip a water path after repeated failed attempts rather than placing an invalid loop.

* Stop once generated rivers and streams are guaranteed not to create loops, branches, self-intersections, 2x2 water blocks, or water-square contact outside the direct previous/next path order.

Woods environment squares.
