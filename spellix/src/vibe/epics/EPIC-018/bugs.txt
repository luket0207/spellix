Bug-001: Revert battle dice roll timing change from Feature-005

Status

* fixed

Related Feature(s)

* Feature-005: Speed up battle turn modal and dice roll timing
* EPIC-014 Feature-006: Battle dice result visible 2s before animations

Bug Summary

* Feature-005 changed the battle dice roll animation to last only `1 second`.
* This change should be reverted.
* The battle dice roll should use the same duration it had before Feature-005.
* Only the dice roll timing should be reverted.

Suspected Cause

* Feature-005 changed the shared persistent `DiceRoll` duration constant from `2000ms` to `1000ms`; BattlePage uses persistent mode while board dice use the separate temporary timing constants.

Required Behaviour

* Restore the previous battle dice roll animation duration.
* Do not keep the new `1 second` dice roll duration.
* Use the same battle dice roll timing that existed before EPIC-018 Feature-005 was implemented.

Important Scope

* Keep the other Feature-005 changes:

  * battle next-turn modal should still show for only `1 second`.
  * battle new-turn modal should still close instantly when anywhere on the screen is clicked.
* Revert only:

  * battle dice roll animation duration.

Suggested Fix Direction

```js id="c2xjz6"
const BATTLE_DICE_ROLL_DURATION_MS = PREVIOUS_BATTLE_DICE_ROLL_DURATION_MS;
```

* If the old value exists in git/history, restore that exact value.
* If the old value was controlled by a shared constant, use the previous constant again.
* Do not affect board dice roll timing unless battle and board dice intentionally share the same component and previous behaviour requires it.

Out Of Scope

* No changes to battle turn modal timing.
* No changes to click-anywhere-to-close behaviour.
* No changes to dice result display.
* No changes to post-roll battle animation timing.
* No changes to board dice timing unless it is technically unavoidable.
* No unrelated battle pacing changes.

Testing Required

* Start a battle.
* Roll the battle dice.
* Confirm the dice roll animation uses the same duration it had before Feature-005.
* Confirm it no longer uses the shortened `1 second` timing.
* Confirm the final dice result still appears correctly.
* Confirm battle animations still start after the correct result flow.
* Confirm the battle next-turn modal still auto-closes after `1 second`.
* Confirm clicking anywhere still closes the battle new-turn modal instantly.
* Confirm there are no console errors.
* Update `testing.txt` before marking this bug fixed.

Attempted Fixes

* Updated the focused duration and battle-flow tests first to require the previous 2-second persistent roll while retaining the 1-second modal assertions; the pre-fix run failed at the shortened roll boundaries and passed both modal checks.

Final Fix

* Restored `PERSISTENT_ROLL_DURATION_MS` from `1000` to `2000` and adjusted only battle-roll timing expectations for normal, forced, frozen-player, and enemy paths.
* Preserved the 1-second battle turn modal, click-anywhere dismissal, 2-second result phase, battle effect timings, and 1.5-second temporary board dice timings.

Bug-003: Hide settings button after movement dice has been rolled

Status

* fixed

Related Feature(s)

* Feature-012: Only show settings button on gameplay page
* Feature-011: Add save and load game using base64 text file
* EPIC-016 Feature-008: Trigger board events based on landed environment

Bug Summary

* The settings button should only be available on the gameplay page before the player has rolled for movement.
* Once the player rolls the board movement dice, the settings button should disappear.
* This prevents players from opening settings during movement, landing resolution, or event transitions.

Required Behaviour

* On the gameplay page, show the settings button only when:

  * the current player has not rolled the board movement dice yet.
  * the game is in the normal pre-roll gameplay state.

* Hide the settings button once:

  * the movement dice has been rolled.
  * valid movement squares are being shown.
  * the player is choosing where to move.
  * movement animation is happening.
  * the landing event is being resolved.
  * the game is waiting to route to battle, decision, river, cave, hazard, loot chest, village, tower, boss, or any other event.

Suggested Visibility Rule

```js id="xnaz9n"
const shouldShowSettingsButton =
  location.pathname === "/gameplay" &&
  boardTurnPhase === "preRoll";
```

* Use the actual route/state names from the project.
* The important part is that settings is only visible during the safe pre-roll state.

Roll Again Requirement

* If Roll Again happens, it is still the same turn.
* After the Roll Again modal closes and the player is waiting to roll again, the settings button should remain hidden.
* Roll Again should not reset settings availability.

Next Turn Requirement

* When the turn advances to the next player and the next-turn modal has completed, the gameplay page returns to pre-roll state.
* At that point, the settings button can appear again.

Save Game Interaction

* Save Game from Feature-011 is inside settings.
* Because settings is hidden after rolling, players should only be able to save during the safe pre-roll gameplay state.
* This avoids saving during mid-turn or mid-event states.

Out Of Scope

* No changes to settings menu content.
* No changes to End Game behaviour.
* No changes to movement rules.
* No changes to Roll Again logic beyond settings visibility.
* No changes to event resolution.

Testing Required

* Open gameplay page at the start of a turn.
* Confirm settings button appears.
* Roll the movement dice.
* Confirm settings button disappears immediately.
* Confirm settings remains hidden while valid movement squares are highlighted.
* Move the player.
* Confirm settings remains hidden during movement animation.
* Confirm settings remains hidden while the landing event resolves.
* Trigger Roll Again.
* Confirm settings remains hidden before the extra roll.
* Advance to the next player.
* Complete the next-turn modal.
* Confirm settings button appears again before the new player rolls.
* Confirm Save Game cannot be accessed after rolling.
* Confirm there are no console errors.
* Update `testing.txt` before marking this bug fixed.

Attempted Fixes

* Added focused pre-fix coverage for the movement-roll lifecycle; it failed because settings remained available after rolling and no turn-level rolled state existed.

Final Fix

* Added a movement-dice-rolled flag to game state, set it as soon as a valid movement roll begins, retained it for same-turn flows such as Roll Again, and reset it only when play advances to another player.
* Limited the gameplay settings button to the safe pre-roll state and kept it hidden while next-turn or respawn transitions are pending, which also prevents Save Game access after rolling.
