Feature-001: Procedural environment and feature generation for board

Status

* done

Goal

* Procedurally generate the non-fixed parts of the 31x31 board.

* Preserve the existing fixed board areas:

  * Start Area
  * Top-left Elite Battle area
  * Bottom-right Elite Battle area
  * Boss Battle area

* Divide the board into easy and hard sections using an invisible diagonal split.

* Generate environment clusters based on the defined environment rules.

* Fill remaining empty squares with Field.

* Randomly place four 2x2 feature areas after environment generation.

* Render each environment type through its own component and associated CSS file so appearances can be changed easily later.

Scope

* Use the existing board generation logic from EPIC-001.

* Use the existing game context.

* Keep the board size at 31x31.

* Keep each square at 30x30px.

* Keep the full board at 930x930px.

* Do not change the fixed board areas created in EPIC-001.

* Generate procedural environments only on squares that are not already part of a fixed area.

* Add an invisible board-section split from the top-left Elite Battle area to the bottom-right Elite Battle area.

* Treat the bottom-left side of this split as the easy section.

* Treat the top-right side of this split as the hard section.

* Use the easy/hard section rules to decide where each environment can appear.

* Generate environment clusters before filling the remaining squares.

* Fill all remaining empty non-fixed squares with Field.

* Place four feature areas after environment generation:

  * Two feature areas in the easy section.
  * Two feature areas in the hard section.

* Each feature area should be 2x2.

* Feature areas should be marked orange.

* Feature areas should work as one grouped feature area in board data.

* Feature placement must keep features at least 3 squares away from:

  * Other generated features.
  * Start Area.
  * Top-left Elite Battle area.
  * Bottom-right Elite Battle area.
  * Boss Battle area.

* Store the final generated board in game context.

* Display the generated board on the gameplay page.

* Keep UI changes limited to rendering the generated board square appearances.

* Each environment square type should render through its own React component.

* Each environment component should live in its own folder.

* Each environment component folder should include its own associated CSS file.

* This is required so each environment appearance can be changed easily later without editing one large board rendering file.

* Use `.jsx` for each environment component.

* Use `.css` for the associated environment component styles.

* Use `.js` for pure board generation helpers where possible.

* Use `.jsx` only for files that contain JSX.

Environment Component Structure

* Create a component folder for each environment type.
* Each folder should contain the environment component and its CSS file.
* Use lowercase folder and file names.
* Keep each component small and focused only on rendering that environment square.
* Do not put all environment rendering styles into one large shared board CSS file.
* Do not create a broad styling system or design token system.
* Do not make decorative design decisions beyond the requested environment appearances.

* The board uses zero-based coordinates.

* `x` increases from left to right.

* `y` increases from top to bottom.

* Top-left square is `{ x: 0, y: 0 }`.

* Bottom-right square is `{ x: 30, y: 30 }`.

* The invisible section split runs diagonally from the top-left Elite Battle area to the bottom-right Elite Battle area.

* Use this split to separate:

  * Easy section: bottom-left side of the board.
  * Hard section: top-right side of the board.

* Use the simplest clear coordinate rule for this split and document the choice.

* Suggested rule:

  * Easy section: `y >= x`
  * Hard section: `y < x`
