Feature-001: Implement Small Heal, Heal, and First Aid potion behaviour

Status

* done

Completion Notes

* Added healing effects for Small Heal at 30%, Heal at 60%, and First Aid at 50% of the player’s current max health.
* Rounded each heal amount to the nearest multiple of 5 and clamped final current health to max health, including max-health increases from committed Light Green tokens.
* Applied healing atomically in the existing confirmed potion-consumption action, so each potion is removed from its slot, respects its existing Board/Battle availability and one-use limit, and never enters Active Potion.
* Added one green Font Awesome flask animation over the current player image on the Board and the battle player image in Battle.
* The animation grows from the image centre to its width, shakes three times, fades out, and removes itself after its specified 1.5-second animation.
* No confirmation modal, turn-limit, enemy health, damage, Light Green token, route, or unrelated UI behavior was changed.

Related Feature

* EPIC-012 Feature-001: Add potion trigger UI and confirmation flow for Board and Battle potions
* EPIC-012 Feature-002: Add one-potion-per-turn limits and Active Potion gameplay section
* EPIC-012 Feature-003: Replace potion data with updated EPIC-012 source-of-truth table

Goal

* Implement the behaviour for the first three healing potions:

  * Small Heal
  * Heal
  * First Aid
* These potions restore health to the player who uses them.
* They differ only by availability and healing percentage.

Potion Behaviour Summary

```txt id="0dyf6u"
Small Heal: recover 30% HP, usable from Board or Battle.
Heal: recover 60% HP, usable from Board or Battle.
First Aid: recover 50% HP, usable from Battle only.
```

Healing Calculation Requirement

* Healing is calculated as a percentage of the player’s full health value.
* The result must be rounded to the nearest multiple of 5.
* The player’s current health then increases by that rounded amount.
* The player can never be healed above their full health.

Suggested helper:

```js id="8p35ee"
function roundToNearestFive(value) {
  return Math.round(value / 5) * 5;
}

function getPotionHealAmount(maxHealth, percentage) {
  return roundToNearestFive(maxHealth * percentage);
}
```

Example 1

```txt id="kum7bl"
Player health: 25 / 110
Potion: Heal
Heal percentage: 60%

60% of 110 = 66
66 rounds to nearest multiple of 5 = 65

New health: 90 / 110
```

Example 2

```txt id="wqqllj"
Player health: 40 / 115
Potion: Small Heal
Heal percentage: 30%

30% of 115 = 34.5
34.5 rounds to nearest multiple of 5 = 35

New health: 75 / 115
```

Example 3

```txt id="y1dbrn"
Player health: 80 / 100
Potion: Heal
Heal percentage: 60%

60% of 100 = 60
New health would be 140 / 100
Clamp to full health.

Final health: 100 / 100
```

Health Clamp Requirement

* Healing must never increase current health beyond max health.
* Use the player’s current full health value, including any Light Green token max-health increases.
* The final current health should be:

```js id="md0fak"
Math.min(currentHealth + healAmount, maxHealth)
```

Potion Consumption Requirement

* These potions are consumed when used.
* They should be removed from the player’s potion slots after the normal use confirmation flow.
* These potions never need to go into the Active Potion section.
* They do not persist after use.

Healing Animation Requirement

* When a healing potion is successfully used, show a green potion bottle animation over the player’s image.
* Use the same Font Awesome potion icon already used for potions.
* The icon should be green.
* The animation should take 1.5 seconds total.

Board Animation Placement

* If the potion is used on the board:

  * show the green potion bottle over the player image at the top of the gameplay UI.

Battle Animation Placement

* If the potion is used in battle:

  * show the green potion bottle over the player’s battle image.

Animation Behaviour

* The potion bottle should:

  * start from the centre of the player image.
  * grow outward from the centre.
  * expand until it matches the width of the player image.
  * shake 3 times.
  * fade out.
* Total animation duration: 1.5 seconds.

Suggested CSS direction:

```css id="uqahhc"

  left: 50%;
  top: 50%;
  width: 0;
  transform: translate(-50%, -50%) scale(0);

  pointer-events: none;

    width: 0;

    opacity: 1;
  }

    width: 100%;
    transform: translate(-50%, -50%) scale(1);
    opacity: 1;
  }

  45% {
    transform: translate(-53%, -50%) scale(1);
  }

  60% {
    transform: translate(-47%, -50%) scale(1);
  }

  75% {
    transform: translate(-52%, -50%) scale(1);
  }

  100% {
    width: 100%;
    transform: translate(-50%, -50%) scale(1);
    opacity: 0;
  }

```

* Exact class names can vary.
* The important requirements are growth, 3 shakes, fade out, and 1.5 second total duration.

Expected Behaviour

* Heal restores 60% of max health, rounded to nearest 5.
* First Aid restores 50% of max health, rounded to nearest 5.
* Healing uses the player’s current max health.
* Healing cannot exceed max health.
* Healing potions are consumed immediately after use.
* Healing potions do not enter Active Potion.
* Board healing shows the animation over the top UI player image.
* Battle healing shows the animation over the battle player image.
* The animation uses a green potion bottle icon.
* The animation lasts 1.5 seconds.

Out Of Scope

* No changes to one-potion-per-turn limits.
* No changes to enemy healing.
* No changes to damage logic.
* No changes to Light Green token behaviour.
* No unrelated battle or board UI redesign.

Feature-002: Implement Roll Choice potion behaviour

Status

* done

Completion Notes

* Added the localized Roll Choice modal after the existing use confirmation, with the required `larger-text` question and six global Button choices in two rows of three.
* Delayed Roll Choice consumption and the one-potion-per-turn lock until a valid value from 1 through 6 is selected.
* Stored one shared `nextForcedRoll` value on the player so the next player dice roll can be forced in either Board or Battle context.
* Added a non-immediate forced result input to the existing DiceRoll component, preserving the existing random and debug forced-request paths.
* Board activation moves Roll Choice to Active Potion with the chosen number over the PotionIcon in the English font; Battle activation does not create Board Active Potion state.
* The forced value and any Board Roll Choice Active Potion are removed as soon as the one forced roll resolves, so later rolls return to normal random generation.
* The choice modal has no separate cancel control; confirmation does not consume or lock the potion, and successful number selection completes activation.
* No normal dice odds, multi-dice potions, battle damage, board movement rules, routes, or unrelated Active Potion styling were changed.

Related Feature

* EPIC-012 Feature-001: Add potion trigger UI and confirmation flow for Board and Battle potions
* EPIC-012 Feature-002: Add one-potion-per-turn limits and Active Potion gameplay section

Goal

* Implement the behaviour of the Roll Choice potion.
* When used, the player chooses the next dice roll value.
* The next time that player rolls the dice, either on the board or in battle, the dice result is forced to the chosen number.
* If activated from the board, Roll Choice should appear in the Active Potion section until the forced roll happens.

Roll Choice Modal Requirement

* After the normal potion-use confirmation is accepted, show a Roll Choice modal.
* The modal should ask:

```txt id="kta5y5"
What do you want the next roll of the dice to be?
```

* Japanese:

```txt id="y3zvcq"
次のサイコロの出目をいくつにしますか？
```

* The question must use the `larger-text` class.
* The modal should use:

  * wooden modal background.
  * yellow text.
  * correct language font.
  * no `ul` or `li`.

Dice Choice Buttons

* Below the question, show 6 buttons.
* The buttons should be arranged in 2 rows of 3.
* Each button represents one dice result:

  * 1
  * 2
  * 3
  * 4
  * 5
  * 6

Suggested layout:

```txt id="pu8skd"
[1] [2] [3]
[4] [5] [6]
```

* Use the global Button component.
* Buttons should be evenly sized and centred.

* When the player chooses a number, store that number as their next forced dice roll.
* The next time that player rolls the dice:

  * on the board, or
  * in battle,
    the dice result must be the chosen number.

  * show the potion using the potion component.
  * overlay the chosen number on top of the potion icon.
  * use the English font for the number.
* The Active Potion entry should remain visible until the forced dice roll happens.
* As soon as the forced dice roll is used, remove Roll Choice from Active Potion.

Battle Usage Requirement

* Roll Choice can also be used in battle because its availability is `Both`.
* If used in battle:

  * the player still chooses the forced number.
  * the next dice roll by that player is forced.
* If the forced roll is used immediately in battle, it may not need to appear in the board Active Potion section.
* Do not show board Active Potion state unless the potion was activated from the board.

Potion Consumption Requirement

* Roll Choice should be consumed once it has been successfully activated and the chosen number has been stored.
* It should be removed from potion slots according to EPIC-012 rules.
* If the player cancels before choosing a number, do not consume the potion unless the existing confirmation flow already consumed it.
* Prefer consuming only after the player has completed the dice-choice selection, so a modal close/cancel does not waste the potion.

Expected Behaviour

* The modal question uses `larger-text`.
* The modal displays 6 buttons in 2 rows of 3.
* Clicking a number stores that number as the player’s next forced dice roll.
* The forced roll applies to the next board dice roll or battle dice roll by that player.
* The forced roll is used once only.
* Roll Choice used from board appears in Active Potion.
* The chosen number appears on top of the Active Potion potion icon.
* The chosen number uses the English font.
* Roll Choice is removed from Active Potion after the forced roll happens.

Out Of Scope

* No changes to Double Dice or Triple Dice.
* No changes to battle damage logic except using the forced roll result.
* No changes to board movement rules except using the forced roll result.
* No unrelated Active Potion redesign.

Status

* not started

Related Feature

* EPIC-012 Feature-001: Add potion trigger UI and confirmation flow for Board and Battle potions
* EPIC-012 Feature-003: Replace potion data with updated EPIC-012 source-of-truth table

Goal

* Implement the behaviour of the Copy and Paste potion.
* The potion duplicates a token from the player’s token bag.
* The player chooses which token to duplicate.
* If the token bag is full, the player chooses which token to discard or may discard the newly duplicated token.
* This potion is consumed only when it can actually be used.

Pre-Use Token Bag Check

* Before the potion is removed from the player’s potion slots, check whether the player has any tokens in their token bag.
* If the player has no tokens in their token bag, the potion cannot be used.
* Show a modal with this English text:


```txt id="sqc2m3"

```

* All of this modal text should use the `larger-text` class.
* The potion should not be consumed.
* Clicking OK closes the modal.

Important Consumption Rule

* Copy and Paste should not be removed from the player’s potion slots until the potion can actually proceed.
* If the player has no tokens in their token bag:

  * do not consume the potion.
  * do not mark it as successfully used.
  * do not trigger the board one-potion-per-turn lock.
* If the current shared trigger flow removes the potion before this check, add logic to return it safely to the potion slots.

Token Selection Modal Requirement

* If the player has at least one token in their token bag, show a modal listing those tokens vertically.
* Do not use `ul` or `li`.
* Use `div` rows.
* Each row should show:

  * the Token component on the left.
  * a Duplicate button directly to the right.
* Button text:

  * English: `Duplicate`
  * Japanese: `複製`

Suggested structure:

```jsx id="8410b9"
<div className="copy-paste-token-list">
  {tokenBag.map((token) => (
    <div className="copy-paste-token-row" key={token.instanceId}>
      <TokenIcon token={token} showName={true} />
      <Button onClick={() => duplicateToken(token)}>
        {duplicateText}
      </Button>
    </div>
  ))}
</div>
```

Duplicate With Space Requirement

* When the player clicks Duplicate:

  * create a duplicate of that token.
  * if the token bag has space, add the duplicate to the token bag.
  * consume the potion.
  * close the modal.
* The duplicated token should behave like a normal token instance.
* It should not share the same instance id as the original.

Duplicate With Full Bag Requirement

* If there is not enough space in the token bag:

  * keep the player in the same modal flow.
  * ask which token they want to discard.
  * The player may discard:

    * the newly duplicated token, meaning nothing is added.
    * any existing token in the token bag, replacing it with the newly duplicated token.
* This must all happen within the same modal flow.
* Do not send the player to the full Spell Token Assignment screen.

Discard Choice Requirement

* Show the duplicated token clearly.
* Show existing token bag tokens as discard choices.
* Do not use `ul` or `li`.
* Each discard option should use the token component and a button.
* Include an option to discard the newly duplicated token.

Suggested labels:

Japanese may be added as:

```txt id="2eji1f"

このトークンを捨てて複製トークンを残す
```

* Copy and Paste is consumed when a duplicate choice successfully resolves.
* It should be consumed if:

  * the duplicated token is added to the token bag.
  * an existing token is discarded and replaced with the duplicated token.
  * the player chooses to discard the newly duplicated token after seeing the full-bag replacement choices.
* It should not be consumed if:

  * the player has no token in their token bag at the initial check.
  * the player cancels before choosing a token, if cancel is supported.

Active Potion Requirement

* Copy and Paste never needs to go into the Active Potion section.
* It should be consumed when used.

Expected Behaviour

* Copy and Paste checks token bag contents before being consumed.
* If token bag is empty, an error modal appears and the potion is not consumed.
* If token bag has tokens, a vertical token list appears.
* Each token row has the token component on the left and Duplicate button on the right.
* Clicking Duplicate adds a duplicate if there is space.
* If the bag is full, the player chooses what to discard within the same modal.
* The player can discard the newly duplicated token.
* The player can discard an existing token and keep the duplicate.
* The potion does not enter Active Potion.
* No `ul` or `li` is used.

Out Of Scope

* No changes to token bag capacity.
* No changes to token rarity.
* No changes to token effects.
* No changes to Spell Token Assignment.
* No unrelated token UI redesign.

* Do not weight by rarity for this reward choice.
* Common and Rare tokens are equally eligible.

Suggested generation direction:

```js id="dxhb32"
const firstToken = getRandomTokenFromAllTokens();
const secondToken = getRandomTokenFromAllTokensExcluding(firstToken.id);
```

Reward Add Requirement

* When the player chooses one of the two offered tokens:

  * add that token to the player’s token bag.
  * show success text in the same modal.
* English:

```txt id="aiatyi"
The token was added to your token bag
```

* Japanese:

```txt id="wnsx9k"
トークンがトークンバッグに追加されました。
```

* Because 3 tokens were discarded first, there should be space for the new token.
* The gained token should be a new token instance.

Potion Consumption Requirement

* Buy and Sell is consumed only after the chosen new token has been added to the token bag.
* It should not go into Active Potion.
* It should not be consumed if:

  * the player has fewer than 3 tokens.
  * the player cancels during discard selection.
* It should be consumed if:

  * 3 tokens were discarded.
  * a reward token was chosen.
  * the reward token was added.

Flow Summary

```txt id="mp3fji"
Use Buy and Sell
→ check token bag has at least 3 tokens
→ if not, show error and stop
→ if yes, choose 3 tokens to discard
→ player may cancel
→ discard selected 3 tokens
→ show 2 different random token choices
→ player chooses 1
→ add chosen token to token bag
→ show success text
→ consume potion
→ continue play
```

Expected Behaviour

* Buy and Sell checks for at least 3 token-bag tokens before use.
* If not enough tokens, a `larger-text` modal appears and the potion is not consumed.
* If enough tokens, player can select exactly 3 tokens.
* Discard button is disabled until exactly 3 tokens are selected.
* Cancel stops the flow without consuming the potion.
* Discard removes the selected 3 tokens.
* Two different random token options appear.
* All tokens have equal chance to appear.
* Player chooses one token.
* Chosen token is added to token bag.
* Success text appears in the same modal.
* Potion is consumed after the token is added.
* Buy and Sell does not enter Active Potion.

Out Of Scope

* No rarity weighting.
* No choosing more or fewer than 3 discarded tokens.
* No potion rewards.
* No Active Potion behaviour.
* No unrelated token bag redesign.
* No changes to token bag capacity.
