Bug-001: Reward token assignment should use shared Spells modal-style drag-and-drop component

Status

* fixed

Related Feature

* Feature-003: Add battle reward generation and reward assignment flow

Bug Summary

* Part 2 of reward token assignment is currently wrong.
* When the player chooses a token reward, they should be taken to a screen that looks and behaves almost identically to the Spells modal.
* The player should be able to drag the new reward token into:

  * one of their spell slots.
  * their token bag.
  * a discard area.
* This same underlying drag-and-drop spell assignment UI should also be used by the normal Spells modal.
* The reward-token-only parts should not appear in the normal Spells modal.

Required Fix

* Refactor the existing Spells modal drag-and-drop UI into a reusable component.
* Use that same component for:

  * the normal Spells modal.
  * the reward token assignment screen.
* The two screens should share the same base layout and behaviour.
* The reward token assignment screen should add reward-specific areas and rules.
* The normal Spells modal should not show:

  * new reward token area.
  * discard area for the new reward token.
  * reward assignment confirmation flow unless already needed for normal spell editing.

Shared Component Requirement

* Create a reusable spell/token assignment component.
* Suggested component responsibility:

  * display spell slots.
  * display token bag.
  * support dragging tokens into valid places.
  * enforce slot capacity.
  * enforce token bag capacity.
  * support save/confirm behaviour.
  * support cancel behaviour where relevant.
* The component should be configurable so it can run in different modes.
* Suggested modes:

```js id="4wnz2c"
mode: "spellsModal" | "rewardAssignment"
```

* Exact prop names can vary.
* Avoid duplicating two separate versions of the same drag-and-drop UI.

Reward Token Assignment Screen Requirement

* After the player chooses a token reward, show the reward assignment screen.
* This screen should look identical to the Spells modal, except for the reward-specific additions.
* It should show:

  * the player’s spell slots.
  * the player’s token bag.
  * the new reward token.
  * a discard area with a Font Awesome trash can icon.
* The player should be able to drag the new token into:

  * a spell slot.
  * the token bag.
  * the discard area.
* The player should be able to confirm only after the new reward token has been resolved.
* Resolved means:

  * placed into a spell slot.
  * placed into the token bag.
  * discarded.

New Reward Token To Spell Slot Requirement

* If the player drags the new reward token into a spell slot:

  * place it in that spell slot if valid.
  * respect existing spell slot capacity rules.
  * the token becomes committed after confirmation.
  * after confirmation, the token cannot be moved.
* The player should be able to review the placement before confirming.
* Do not duplicate the reward token.
* Do not also place the reward token in the token bag.

New Reward Token To Token Bag Requirement

* If the player drags the new reward token into the token bag and there is space:

  * add the new token to the token bag.
  * allow the player to confirm.
* If the player drags the new reward token into a full token bag:

  * show a prompt asking which existing token in the token bag should be removed.
  * when the player clicks an existing bag token, remove that token.
  * place the new reward token into the token bag.
  * allow the player to confirm.
* The player should not be able to exceed the token bag maximum.
* The replacement prompt should be clear and not permanently remove anything until the player confirms, unless existing app behaviour already commits token bag choices immediately.

Discard Area Requirement

* The reward assignment screen should include a discard area.
* The discard area should use a Font Awesome trash can icon.
* If the new reward token is dragged onto the discard area:

  * discard the new reward token.
  * allow the player to complete the reward flow.
* If a token from the token bag is dragged onto the discard area:

  * discard that token from the token bag.
  * automatically place the new reward token into the token bag.
* This token bag discard behaviour is only needed for the reward assignment screen.
* The discard area should make it clear that tokens dragged there will be removed.
* Do not show this reward discard area in the normal Spells modal.

Token Bag Replacement Requirement

* The player has two valid ways to make room in a full token bag:

  * drag the new reward token into the full token bag, then choose which current bag token to remove.
  * drag an existing token bag token to the trash, causing the new reward token to take its place automatically.
* Both routes should result in:

  * exactly one existing bag token removed.
  * the new reward token added to the token bag.
  * the bag staying at its maximum capacity.
* The new reward token should not be duplicated.
* The removed bag token should be listed or otherwise made clear before confirmation if the current UI supports review.

Normal Spells Modal Requirement

* The normal Spells modal should use the same shared component.
* The normal Spells modal should continue to support existing behaviour:

  * moving uncommitted token bag tokens into spell slots.
  * saving changes.
  * cancelling changes.
  * respecting slot capacity.
  * respecting committed token rules.
* The normal Spells modal should not show:

  * a new reward token.
  * a reward token placement prompt.
  * the reward discard/trash area.
  * full-bag reward replacement prompts.
* The normal Spells modal should look and behave the same as before from the player’s perspective, except that the internal implementation is now shared.

Confirmation Requirement

* Reward token assignment should not be final until the player confirms.
* If the player places the reward token into a spell slot and confirms:

  * commit the token into that spell slot.
* If the player places the reward token into the token bag and confirms:

  * save it into the token bag.
* If the player discards the reward token and confirms:

  * do not add it anywhere.
* If the player replaces a token bag token and confirms:

  * remove the selected old bag token.
  * add the new reward token.
* If the player cancels before confirming:

  * do not apply the reward token placement.
  * do not remove any existing token bag tokens.
* If the reward flow must not be cancellable, then the player must still resolve the reward by placing or discarding it before continuing.

Expected Behaviour

* Token reward assignment opens a Spells modal-style screen.
* The screen shows spell slots and token bag in the same style as the normal Spells modal.
* The reward token can be dragged into a spell slot.
* The reward token can be dragged into the token bag.
* The reward token can be dragged onto a Font Awesome trash can to discard it.
* Dragging the reward token into a full token bag prompts the player to choose which existing bag token to remove.
* Dragging a current token bag token onto the trash removes that bag token and places the new reward token into the bag automatically.
* The normal Spells modal and reward assignment screen use the same underlying component.
* Reward-specific UI is hidden in the normal Spells modal.
* Existing Spells modal behaviour is not broken.

Out Of Scope

* No changes to reward generation chances.
* No changes to token rarity.
* No potion reward assignment changes.
* No potion capacity changes.
* No token effect changes.
* No battle reward balancing changes.
* No battle logic changes.
* No gameplay movement changes.
* No save/load persistence.
* No unrelated reward page redesign.
