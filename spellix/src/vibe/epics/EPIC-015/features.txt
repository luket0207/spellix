Goal

* Add a new page called the `Decision` page.
* A decision is a question with 3 possible answers.
* Each answer has a percentage chance of producing a good, neutral, or bad outcome.
* In this feature, implement:

  * the Decision page route.
  * the Decision page layout.
  * the decision question data.
  * random question selection.
  * 3 full-width answer buttons.
  * weighted good / neutral / bad outcome resolution.
  * temporary outcome display.
  * Continue flow back to the board.
  * debug menu access.
* Actual rewards and punishments are out of scope for this feature.

Concept Summary

* A decision contains:

  * one question.
  * three fixed choices.
  * each choice has a good, neutral, and bad chance.
  * each outcome has:

    * an outcome result, such as `Gain a Small Heal potion`, `Nothing`, `Lose a token`, or `Lose your next turn`.
    * outcome text, usually a longer narrative sentence explaining what happened.
* The player must choose one of the 3 options.
* The game then rolls against that choice’s good / neutral / bad chances.
* For now, the game only displays the selected outcome.
* Later features will implement the actual outcome effects.

Terminology Note

* The source table uses `Choice Natural Chance`.
* In implementation, treat this as `Choice Neutral Chance`.
* Use `neutral` everywhere in code unless the existing project already uses another spelling.

Outcome Resolution Requirement

* When a player clicks a choice button, use that choice’s chances to randomly decide the outcome.
* Possible outcomes:

  * good.
  * neutral.
  * bad.
* Actual outcome effects are out of scope.
* For now, display:

  * the outcome text.
  * the outcome result.
* Example:

  * outcome text: `The voice belongs to a grateful spirit, which rewards your kindness.`
  * outcome result: `Gain a Small Heal potion`

Suggested Resolution Logic

```js id="z4e6qp"
function resolveDecisionOutcome(chances) {
  const roll = Math.random() * 100;

  if (roll < chances.good) {
    return "good";
  }

  if (roll < chances.good + chances.neutral) {
    return "neutral";
  }

  return "bad";
}
```

Chance Validation Requirement

* Each choice’s good, neutral, and bad chance should total `100`.
* If a choice does not total `100`, log a clear development warning.
* If an outcome has a `0` chance, it should never be selected.
* Some neutral outcomes in the table are `N/A` because their chance is `0`.
* Do not display `N/A` outcomes unless bad data causes them to be selected.

* The outcome result should:

  * be centred.
  * be smaller than the narrative text.
  * use the correct language font.
  * have appropriate margin spacing from the narrative text.
* The Continue button should appear below the outcome result.

Feature-002: Implement Decision page rewards and punishments

Status

* done

Related Feature(s)

* Feature-001: Add Decision page with random question, choice resolution, and placeholder outcome display

* EPIC-010 Feature-015: Redesign Spell Token Assignment page

Goal

* Implement the actual rewards and punishments from Decision page outcomes.
* Use the decision data added in Feature-001.
* Neutral outcomes should continue to do nothing except display the outcome text.
* Good outcomes should grant rewards.
* Bad outcomes should apply punishments.
* Reuse existing reward and punishment mechanisms from battle, death, cave, and potion flows wherever possible.

Core Rule

* The Decision page should now resolve the chosen outcome fully before returning to the board.
* The Continue button should only return to the board once the outcome has been displayed and any required reward or punishment flow has finished.

Outcome Categories

* Decision outcomes can currently produce these result types:

  * Nothing
  * Gain a specific potion
  * Gain a random common potion
  * Gain a random rare potion
  * Gain a specific token rarity
  * Gain a common token
  * Gain a rare token
  * Gain a token
  * Lose X health
  * Lose a token
  * Lose a random potion
  * Lose your next turn

Neutral Outcome Requirement

* Neutral outcomes always do nothing.
* When a neutral outcome is selected:

  * show the outcome narrative text.
  * show the outcome result text, usually `Nothing`.
  * show the Continue button.
* Clicking Continue should:

  * return to the board.
  * advance the turn to the next player.
  * show the next-turn modal as usual.

Good Outcome: Gain Potion

* Potion rewards can be:

  * a specific potion, such as `Small Heal`, `Cauldron`, `Freeze`, `Thaw`, or `First Aid`.
  * a random common potion.
  * a random rare potion.
  * a random potion from the requested rarity group.
* Use the potion data from the current source-of-truth potion table.
* When a potion reward is granted:

  * display the outcome narrative text.
  * display the outcome result text.
  * then show the actual Potion component for the potion being gained.
  * include the potion name.
  * include the potion tooltip.
* If the player has room in their potion slots:

  * add the potion to the player’s potion slots.
  * allow Continue to return to the board and advance the turn.
* If the player’s potion slots are full:

  * use the usual potion replacement flow.
  * allow the player to discard the new potion.
  * or allow the player to discard one existing potion and keep the new potion.
  * this should match the existing battle potion reward flow.
* Once potion reward resolution is complete:

  * Continue returns to the board.
  * the turn advances to the next player.

Good Outcome: Gain Token

* Token rewards can be:

  * a common token.
  * a rare token.
  * a token from both common and rare options.
  * a specific token category if later added to decision data.
* Token rewards should use the same method battle uses to award and assign tokens.
* Use the existing Spell Token Assignment component with the trash ability.
* This should match battle token reward behaviour.
* When a token reward is granted:

  * display the outcome narrative text.
  * display the outcome result text.
  * show the token reward through the assignment flow.
* The player should be able to place or trash the token using the same rules as battle rewards.
* Once token assignment is complete:

  * return to the board.
  * advance the turn to the next player.

* This is a new mechanism.
* When this punishment is inflicted:

  * store a one-time skip-turn flag on the affected player.
  * complete the current Decision page normally.
  * return to the board.
  * advance to the next player as usual.

Suggested Logic Direction

```js id="iifoz0"
function resolveDecisionOutcome(choice, goodDecisionsActive) {
  const { good, neutral, bad } = choice.chances;

  if (goodDecisionsActive) {
    const safeTotal = good + neutral;

    if (safeTotal <= 0) {
      return "good";
    }

    const roll = Math.random() * safeTotal;

    if (roll < good) {
      return "good";
    }

    return "neutral";
  }

  const roll = Math.random() * 100;

  if (roll < good) {
    return "good";
  }

  if (roll < good + neutral) {
    return "neutral";
  }

  return "bad";
}
```
