Feature-005: Dice roll, player movement, and gameplay screen layout

Status

* done

Goal

* Implement dice rolling for the current player.
* Highlight the board spaces the current player can legally move to.
* Allow the current player to click a valid destination and move there.
* End the current player’s turn after they move.
* Split the gameplay screen into a board panel and a gameplay controls/info panel.

Scope

* Use the existing game context.

* Use the existing player turn system from Feature-003.

* Use the existing board and player position data from Feature-004.

* Update the gameplay screen layout so it has two main panels:

  * Left panel: the game board.
  * Right panel: current turn info, dice controls, modals/triggers, and any other non-board gameplay UI.

* Move the current turn display into the right-side panel.

* Store the current dice result in game context or local gameplay state, whichever is smallest and clearest.

* After the dice result is known, calculate all legal destination spaces for the current player.

* Highlight legal destination spaces on the board with the requested opaque blue selection highlight.

* The highlight should be functional and lo-fi.

* The player moves by clicking one highlighted destination space.

* When the player clicks a valid highlighted destination, update that player’s position.

* After the player moves, clear the dice result and legal move highlights.

* After the player moves, end the current player’s turn.

* Turn ending should use the existing next-turn behaviour from Feature-003.

* Players cannot move diagonally.

* Movement must be orthogonal only:

  * up
  * down
  * left
  * right

* The dice value is the number of movement steps the player may use.

* Grouped board areas count as one movement space even though they contain multiple board squares.

* Grouped board areas include:

  * Start Area
  * Elite Battle areas
  * Boss Battle area

* Use `.jsx` for all React component/page/context files that contain JSX.

* Use `.js` for pure movement or dice helper logic if no JSX is needed.

Movement Rules

* A dice roll produces a value from 1 to 6.
* The current player may move exactly that many movement steps.
* Movement cannot be diagonal.
* A normal board square counts as one movement space.
* A grouped area counts as one movement space.
* Moving into a grouped area costs 1 movement step.
* Moving out of a grouped area costs 1 movement step.
* Moving through a grouped area should not cost extra because of its internal square size.
* A grouped area is adjacent to another movement space if any square in the grouped area shares an edge with that movement space.
* The board should calculate reachable destinations using movement spaces, not just raw visual squares.
* For grouped destinations, the whole grouped area may be highlighted.
* Clicking any highlighted square inside a grouped area should count as selecting that grouped area.

Suggested Movement Model

* Treat the board as movement nodes.
* A normal square is one movement node.
* Each grouped area is one movement node.
* Each node can connect to adjacent nodes through shared edges.
* Reachable destinations can be calculated from the current player’s node using the dice roll value.
* This keeps grouped areas working as one movement space.

```js
    {
      type: "square",
      x: 4,
      y: 28
    },
    {
      type: "area",
      areaType: "start-area"
    }
  ]
}
```
