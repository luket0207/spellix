Feature-001: Create reusable dice roll component with persistent and temporary modes

Status

* done

Completion Notes

* Added one shared `DiceRoll` component with persistent and temporary modes.
* Persistent mode remains on the battle page, accepts repeated manual rolls, and reports each completed result to the page without changing battle state.
* Temporary mode now owns the gameplay dice result, keeps the modal open for the full 2 second roll and 2 second result sequence, and returns the same result used for movement highlighting.
* Reused the existing shared `Modal`, gameplay movement helpers, battle page layout, and existing turn flow.
* Anywhere Mode keeps its existing one-use movement behavior and label while using the same locked temporary dice sequence; its numerical roll does not limit Anywhere Mode destinations.
* Intentionally did not add battle attacks, turn advancement, spell execution, sound, persistence, dependencies, routes, or unrelated visual changes.

Goal

* Create a reusable six-sided dice roll component.
* The dice component should support both persistent and temporary usage.
* The component should be usable inside modals and outside modals.
* The component should be easy to trigger.
* The component should return the rolled value to whatever requested the roll.
* Add the persistent dice component to the battle page.
* Replace the existing gameplay dice result modal number with the temporary dice component.

Scope

* Create a reusable dice component.
* The dice should be six-sided.
* The dice should visually animate when rolling.
* The dice should land on the side that represents the roll result.
* The dice should provide the result value back to the parent component or calling flow.
* The dice should support two modes:

  * persistent.
  * temporary.
* Persistent mode should stay on screen and be manually rolled.
* Temporary mode should perform one automatic roll and then finish.
* Use the persistent dice component on the battle page.
* Use the temporary dice component inside the gameplay dice roll modal.
* Keep battle logic integration out of scope for this feature.
* Keep the component reusable and not tied only to gameplay or battle.

Component Requirements

* The dice component should render a six-sided dice.
* The dice should be able to roll and produce a value from 1 to 6.
* The rolled value should be returned to the parent through a callback.
* Suggested callback prop:


* The component should support a `mode` prop.
* Suggested mode prop:


* The component should not assume where it is being rendered.
* It should work inside a modal.
* It should work outside a modal.
* It should not directly control global turn state.
* It should not directly control battle state.
* It should only report the roll result and manage its own animation/display sequence.

Feature-002: Implement basic dice-driven battle turns with Red, Blue, Orange, and Green token effects

Status

* done

Completion Notes

* Completed the first calculation slice in `src/features/battle/battleTurn.js`.
* Added one pure `calculateBattleTurn` function that uses the same rolled slot for both actors and reads the existing shared spell-slot/token shape.
* Required inputs are `diceResult`, `currentActor`, and `opponent`; each actor supplies `currentHealth`, `guard`, and `spellSlots`.
* The result contains stacked token counts, detailed damage values, next health and guard values, miss status, and ordered Red, Green, Blue, and Orange effect descriptors.
* This slice implements Red damage, Blue guard gain, opponent Orange counter damage, opponent Green reduction, Green-before-guard ordering, opponent guard expiry, health clamping, ignored unsupported colors, and empty/joined misses.
* Completed the second integration slice by initializing every battle with the triggering player as `currentBattleActor`, zero player and enemy guard, and an unresolved turn state.
* The battle page now shows a buttonless player turn modal with the player's colour and image for 2 seconds when an active battle begins.
* The persistent battle dice now accepts an external disabled state and remains locked while the turn modal is visible or the battle is resolving.
* Completed the third integration slice by connecting each completed persistent battle dice roll to `calculateBattleTurn` through one atomic context action.
* Player and enemy health plus both guard values now persist from the selected matching spell slots, including Red damage, Blue guard, Orange counter damage, Green reduction, and opponent guard expiry calculated by the existing helper.
* Completed the fourth integration slice by marking completed calculations as resolving, waiting the required 1-second pause, and alternating between player and enemy actors.
* Every actor transition now reuses the 2-second turn modal with the correct player colour/image or enemy English name/image, and the persistent dice stays disabled until the modal closes.
* Enemy turns use the same manual dice, slot calculation, health/guard persistence, and transition flow as player turns.
* Guard expiry now persists through the full player-to-enemy-to-player integration flow, including an opponent turn that grants guard and a following turn that deals no damage.
* Completed the fifth integration slice by showing the required blue Font Awesome shield directly under the player or enemy image whenever that actor's guard is greater than 0.
* Guard shields are visual-only, use the existing stored guard values, do not render at 0 guard, and disappear immediately when guard expires.
* Completed the sixth integration slice by persisting each calculation's ordered effect descriptors for the resolving turn and sequencing the implemented Red effect before the existing 1-second pause.
* Red uses one combined circle per turn, travels from the current actor toward the opponent, expands and fades at the target as a simple explosion, and remains active for exactly 1 second.
* The dice remains disabled throughout the Red animation and following pause, and the next actor modal does not begin until both have finished.
* Completed the seventh integration slice by adding Green reduction to the same effect queue immediately after Red.
* Green renders only when the calculation reports an actual reduction, radiates from behind the protected actor to 120% of the actor image height, and remains active for exactly 1 second without overlapping Red.
* The separate 1-second pause begins only after all supported Red and Green effects finish.
* Completed the eighth integration slice by adding Blue guard to the same effect queue immediately after Green.
* Blue renders one combined blue circle behind the current actor, grows to 120% of the actor image height, and remains active for exactly 1 second for either player or enemy guard gain.
* The separate 1-second pause now begins only after all supported Red, Green, and Blue effects finish.
* Completed the ninth integration slice by adding Orange counter damage as the final effect in the required Red, Green, Blue, Orange queue.
* Orange uses one combined small circle per turn, travels from the countering opponent toward the original caster, expands and fades at the target, lasts exactly 1 second, and supports both player-to-enemy and enemy-to-player directions.
* The separate 1-second pause now begins only after every calculated supported effect finishes, with no simultaneous animations.
* Completed the tenth and final integration slice by deriving a terminal win/loss outcome from the calculated post-turn health and reusing the existing reward and respawn flows.
* Lethal results clamp health at 0, clear pending effects, stop resolution and actor transition, suppress the next turn modal, and prevent further dice rolls.
* If both actors reach 0 in the same calculation, player loss takes precedence because the battle is resolved from the user player's perspective.
* Feature-002 is complete without adding unsupported token effects, automatic enemy rolls, dependencies, routes, persistence, or unrelated UI changes.
