Bug-001: Spells modal is missing drag-and-drop token setup, initial setup flow, and save/cancel behaviour

Status

* fixed

Related Feature

* Feature-002: Player spell slots, token bag, and spell setup modal

Bug Summary

* The Spells modal is missing major required behaviour from Feature-002.
* The player cannot drag and drop tokens from their token bag into spell slots.
* The starting token setup is missing.
* The initial forced spell setup at the start of each player’s first turn is missing.
* The save and cancel confirmation flows are missing.
* This means much of the spell setup feature has not been implemented according to the brief.

Repro Steps

* Start a new game.
* Begin gameplay.
* Reach a player’s first turn.
* Open the Spells modal, or observe whether it opens automatically.
* Check whether the player has a starting token bag.
* Check whether the token bag contains 5 red tokens and 2 blue tokens.
* Try to drag tokens from the token bag into spell slots.
* Try to save token placement.
* Try to cancel token placement.
* Check whether the player is forced to complete spell setup before rolling dice on their first turn.

Expected Behaviour

* On each player’s first turn, the Spells modal should open automatically before the player can roll dice.
* The first-turn Spells modal should not be dismissible until the player has placed all starting tokens into spell slots and saved.
* Each player should start with:

  * 5 red tokens
  * 2 blue tokens
* Starting spell tokens should be shown visually in a token bag area.
* Spell tokens should be represented as coloured circles matching the token colour.
* Red tokens should appear as red circles.
* Blue tokens should appear as blue circles.
* The player should be able to drag tokens from the token bag into any spell slot.
* The player should have 6 spell slots.
* Each spell slot should hold up to 5 spell tokens by default.
* The player should be able to move newly placed, unsaved tokens between slots during the current modal visit.
* The player should be able to return newly placed, unsaved tokens to the token bag during the current modal visit.
* The player should not be able to move or remove tokens that have already been committed by saving.
* The modal should have a `Save` button.
* The modal should have a `Cancel` button.
* Clicking `Cancel` should show a confirmation message.
* Clicking `Save` should show a confirmation message.
* Saving should commit the token placement into that player’s spell data.
* Cancelling should discard unsaved token placement changes.
* Each player’s spell setup should be saved separately.

Actual Behaviour

* Drag and drop from the token bag to spell slots is missing.
* The starting token bag is missing or not correctly represented.
* The initial forced spell setup flow is missing.
* Spell tokens are not shown as coloured circles in the token bag.
* The save confirmation flow is missing.
* The cancel confirmation flow is missing.
* Feature-002 appears to have been only partially implemented or the brief was not followed.

Required Fix

* Review Feature-002 in `src/vibe/epics/EPIC-003/features.txt`.
* Implement the missing spell setup behaviour from Feature-002.
* Add starting token data for each player:

  * 5 red tokens
  * 2 blue tokens
* Represent tokens visually as simple coloured circles.
* Add a token bag area in the Spells modal.
* Add 6 spell slots in the Spells modal.
* Use an external drag-and-drop library as required by Feature-002.
* Allow tokens to be dragged from the token bag into spell slots.
* Allow newly moved, unsaved tokens to be moved between slots.
* Allow newly moved, unsaved tokens to be returned to the token bag.
* Prevent committed tokens from being moved or removed.
* Enforce the default slot capacity of 5 tokens per spell slot.
* Add the first-turn forced setup flow.
* On a player’s first turn, automatically open the Spells modal before dice rolling.
* Prevent the player from rolling dice until their initial spell setup is saved.
* Prevent the first-turn forced Spells modal from being dismissed before all starting tokens are placed and saved.
* Add the `Cancel` button.
* Add the `Save` button.
* Add the cancel confirmation flow.
* Add the save confirmation flow.
* Save committed spell slot data into that player’s data in game context.
* Keep the implementation lo-fi and functional.
* Do not add decorative token art.

