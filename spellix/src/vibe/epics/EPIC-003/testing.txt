Feature-002: Player spell slots, token bag, and spell setup modal

Test Status

* blocked

Current Slice Covered

* Each player still starts with spell data in game setup:
  * 5 red tokens
  * 2 blue tokens
  * 6 spell slots with max capacity 5
  * `hasCommittedInitialSpells: false` until their first save
* The gameplay panel now forces the current player through first-turn spell setup before `Roll Dice` can be used.
* The Spells modal now shows draggable token circles, a token bag drop zone, six spell-slot drop zones, save/cancel confirmations, and committed-token locking after save.
* The Spells modal now lays out the six spell slots horizontally in left-to-right order, with simple horizontal scrolling as the fallback when the modal is narrower.
* The token source area now stays below the spell slots and is labelled `Starting Tokens` during forced setup and `Token Bag` on later visits.
* The token source area now shows token circles only in both forced setup and later Token Bag visits, with no red/blue count text in either case.
* The Spells modal now detects whether the current draft differs from the saved spell data, disables `Save` when there are no unsaved changes, and closes immediately on `Cancel` when nothing has changed.
* After save, the current player's committed spell slots now render in a compact read-only sidebar section below the `Spells` button with the title `Spells`, empty committed spell slots stay visible without placeholder text, the six columns are labelled only with `1` through `6` inside the bordered slot columns, and all columns share a 150px minimum height within the same read-only grid.

Manual Test Steps

1. Start a game and go to `/gameplay`.
Expected result: The gameplay page renders the board, current-turn sentence, `Roll Dice`, and `Spells`, and the first player immediately gets the forced Spells modal.

2. Inspect the forced Spells modal before moving any tokens.
Expected result: The modal shows 6 spell slots in a horizontal left-to-right row, shows `Starting Tokens` below the slots, does not show red/blue count text there, disables `Cancel`, and keeps `Roll Dice` unavailable.

3. Drag tokens from the token bag into spell slots, including moving at least one unsaved token between slots and back to the bag.
Expected result: Draft token moves work inside the modal, and only unsaved tokens can move.

4. Try to place more than 5 tokens in one spell slot.
Expected result: The slot stops accepting additional tokens after reaching 5 tokens.

5. Click `Save` before all 7 starting tokens are placed.
Expected result: The modal stays open and shows a validation message telling the player to place all 7 starting tokens before saving.

6. After placing all 7 tokens, click `Save`, choose `No`, then click `Save` again and choose `Yes`.
Expected result: `No` returns to the modal with the draft preserved; `Yes` commits the setup, closes the modal, and enables `Roll Dice`.

7. Inspect the right-side gameplay panel after saving, then reopen `Spells`.
Expected result: The sidebar shows a read-only `Spells` section for the current player, the six committed spell slots fit in the compact horizontal layout, committed tokens are no longer draggable, any empty committed slots show no `No committed tokens` placeholder text, the columns show only `1` through `6` instead of `Slot 1` through `Slot 6`, and each column is at least 150px tall.

8. End the turn and reach the next player.
Expected result: The next player gets the same forced first-turn spell setup flow once, while previously committed players keep their saved spell slots.

9. Reopen the Spells modal after the current player has already committed spells.
Expected result: The slot row still appears horizontally, the token source area is still inside the modal below the slots, its heading changes to `Token Bag`, and it still does not show red/blue count text.

10. Reopen the Spells modal for a player with no new token changes and do not move anything.
Expected result: `Save` is disabled, `Cancel` closes the modal immediately, and no cancel confirmation appears.

11. Save a player setup with uneven token counts across different committed spell columns and inspect the gameplay sidebar again.
Expected result: All six committed spell columns remain the same height, shorter columns stretch to match the tallest column, and no token stack is cut off.
