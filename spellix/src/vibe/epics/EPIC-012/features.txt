Feature-001: Add potion trigger UI and confirmation flow for Board and Battle potions

Status

* done

Completion Notes

* Added Board-context Use controls for `Board` and `Both` potions while keeping all owned `Battle` and `Mini` potions visible without active controls and reserving equal button space on every board card.
* Added a centred Battle potion section above the existing dice control that shows only `Battle` and `Both` potions, preserves inventory indexes, aligns cards, and disables Use outside the player turn.
* Added one shared context-eligibility helper and one shared confirmation modal using the existing Modal, Button, PotionIcon, potion translation helpers, and language font classes.
* Added exact English and Japanese Use, question, description subtitle, Yes, and No copy with English fallback.
* Confirming removes only the selected potion instance through the existing game setup context; cancelling leaves inventory unchanged.
* No potion effects, Mini trigger UI, routes, reward behavior, inventory capacity, replacement logic, dice logic, movement logic, dependencies, or unrelated styling/refactors were added.

Related Feature

* EPIC-011 Feature-005: Replace potion data with revamped source-of-truth potion table
* EPIC-011 Bug-012: Update Bridge Builder, Good Decisions, and Cave Runner potion availability to Mini

Goal

* Start implementing potion usage by adding the places where potions can be triggered.
* Add trigger UI for:

  * Board potions from the gameplay board UI.
  * Battle potions from the battle UI.
  * Both potions from both board and battle contexts.
* Add a shared confirmation modal that appears whenever a potion is triggered.
* Remove the potion from the player’s potion slots after confirmed use.
* Do not implement the actual potion effects yet.

Scope

* Add Board potion Use buttons in gameplay UI.
* Add Battle potion section above the battle dice roll.
* Add Battle potion Use buttons.
* Add shared potion-use confirmation modal.
* Remove confirmed potion from the player’s potion slots.
* Support English and Japanese confirmation text.
* Show potion description in the confirmation modal.
* Preserve layout alignment for potion slots with and without buttons.
* Keep Mini potion usage out of scope.

Potion Availability Rules

* Potion availability now controls where the potion can be triggered.
* Supported values are:

```txt id="is5g21"
Board
Battle
Both
Mini
```

* `Board` potions can only be triggered from the gameplay board UI.
* `Battle` potions can only be triggered from the battle UI.
* `Both` potions can be triggered from either the gameplay board UI or the battle UI.
* `Mini` potions are out of scope for this feature.
* Mini potions should not appear in the battle potion section.
* Mini potions should appear in the board potion slots if the player owns them, but they should not have a Use button.

Shared Potion Trigger Confirmation Modal

* Whenever a potion is triggered from anywhere, show a confirmation modal.
* This modal appears before the potion is consumed.
* English question:

```txt id="p5fwff"
Are you sure you want to use X?
```

* Japanese question:

```txt id="crbmqw"
Xを使用してもよろしいですか？
```

* `X` should be replaced with the potion name in the current language.
* English should use the English potion name.
* Japanese should use the Japanese potion name.

Confirmation Modal Text Requirements

* The main question must use the `larger-text` class.
* The modal should use:

  * wooden modal background.
  * yellow text.
  * correct language font.
  * bottom-centred buttons.
  * buttons that are not full width.
* The confirmation modal is a text-focused modal, so the question should be placed in a `<p>` with `larger-text`.

Suggested structure:

```jsx id="ern9a4"
<p className={`larger-text ${languageClass}`}>
  {confirmUsePotionText}
</p>
```

Potion Description Requirement

* Below the confirmation question, show the potion description.
* Add a subtitle above the description.
* English subtitle:

```txt id="f0k5t1"
Potion Description
```

* Japanese subtitle:

```txt id="to8mjs"
ポーションの説明
```

* The subtitle should use normal modal text styling.
* The potion description should use normal-sized text, not `larger-text`.
* The description should use the current language.
* English should show the English potion description.
* Japanese should show the Japanese potion description.

Suggested modal layout:

```txt id="nla764"
Are you sure you want to use X?

Potion Description

Potion description text here.

Yes / No
```

Confirmation Modal Button Behaviour

* The modal should show Yes and No choices.
* If the player chooses No:

  * close the modal.
  * do not remove the potion.
  * do not trigger any effect.
* If the player chooses Yes:

  * remove the potion from the player’s potion slots.
  * close the modal.
  * do not trigger the potion effect yet, because potion effects are out of scope for this feature.

Button translations:

```txt id="hnyqwu"
Yes	はい
No	いいえ
```

Potion Removal Requirement

* When confirmed, the used potion should be removed from the current player’s potion slots.
* Only the selected potion instance should be removed.
* If the player has two copies of the same potion, using one should remove only one copy.
* Empty potion slot behaviour should follow existing potion inventory rules.
* Do not remove anything when the player cancels.

Board Potion Trigger Requirement

* Board potion trigger UI should be added to the potions section within the gameplay UI.
* When a potion with availability `Board` or `Both` is in the player’s potion slots:

  * show a Use button beneath that potion.
* English button text:

```txt id="cc2gxf"
Use
```

* Japanese button text:

```txt id="w0w5c5"
使用する
```

* Clicking this button should open the shared potion-use confirmation modal.
* The potion should not be removed until the player confirms Yes.

Board Potion Visibility Requirement

* All owned potions should still be shown in the gameplay potion section.
* If a potion is not usable on the board:

  * still show the potion.
  * do not show an active Use button beneath it.
* This means:

  * `Board` potions show Use.
  * `Both` potions show Use.
  * `Battle` potions do not show Use on the board.
  * `Mini` potions do not show Use on the board.

Board Potion Layout Requirement

* The potion display must remain neat and aligned even when some potions have Use buttons and others do not.
* Potion cards/slots should stay the same height.
* Potion names, icons, descriptions, and buttons should remain inline with each other.
* A potion without a Use button should reserve the same button area so the layout does not jump.
* Do not allow one potion card to become shorter just because it has no button.

Suggested board potion card structure:

```jsx id="f7kwsb"
<div className="gameplay-potion-card">
  <PotionIcon potion={potion} />

  <div className="gameplay-potion-button-space">
    {canUseOnBoard ? (
      <Button onClick={() => openPotionUseModal(potion)}>
        {useText}
      </Button>
    ) : null}
  </div>
</div>
```

Suggested CSS direction:

```css id="kjbwal"
.gameplay-potion-card {
  display: grid;
  grid-template-rows: auto 42px;
  align-items: center;
  justify-items: center;
}

.gameplay-potion-button-space {
  min-height: 42px;
  display: flex;
  align-items: center;
  justify-content: center;
}
```

* Exact class names and heights can vary.
* The important requirement is that every potion card reserves the same vertical space.

Battle Potion Trigger Requirement

* Add a new potion section inside the same battle UI element as the dice roll.
* This new section should sit above the dice roll.
* The section should be centred.
* Only potions that can be used in battle should appear here.
* Battle-usable potions are:

  * `Battle`
  * `Both`
* Potions with availability `Board` should not appear in the battle potion section.
* Potions with availability `Mini` should not appear in the battle potion section.

Battle Potion Section Layout

* The battle potion section should be centred above the dice roll.
* It should sit inside the same parent element as the dice roll so it visually belongs to the battle controls.
* If the player has no battle-usable potions:

  * do not show an empty broken section.
  * either hide the section or reserve clean spacing according to the existing battle layout.
* If the player has battle-usable potions:

  * show each battle-usable potion.
  * show a Use button beneath each potion.
  * keep all potion cards aligned.

Suggested battle layout:


* Potion names should line up.

* Long potion names should not cause buttons to sit at different heights.

Battle Turn Requirement

* Potions can only be triggered on the player’s turn in battle.
* Do not allow the player to use potions during the opponent/enemy turn.
* If the battle UI remains visible during enemy actions, hide or disable battle potion Use buttons during that period.
* Do not consume a potion unless the player confirms the modal.

Mini Potion Requirement

* Mini potion trigger logic is out of scope for this feature.
* Mini potions should not appear in the battle potion section.
* Mini potions should appear in board potion slots if owned, but they should be unusable there.
* Do not add Mini-specific trigger buttons yet.
* Do not implement River, Cave, or Decision mini-game potion use in this feature.

Both Potion Requirement

* `Both` potions should be usable from:

  * the board gameplay UI.
  * the battle UI.
* They should show a Use button in both contexts.
* Using a Both potion from either context should show the same confirmation modal.
* Confirming should remove the potion from the player’s potion slots.

No Potion Effect Requirement

* Potion effects are out of scope.
* After confirming Yes:

  * remove the potion.
  * close the modal.
  * do not apply heal, damage, teleport, freeze, roll change, or any other effect yet.
* This feature only proves that potions can be triggered and consumed from valid contexts.

Shared Helper Requirement

* Use shared logic to determine whether a potion can be used in a context.
* Avoid separate hardcoded checks across board and battle UI.

Suggested helper:

```js id="xcwq2m"
function canUsePotionInContext(potion, context) {
  if (context === "board") {
    return potion.availability === "Board" || potion.availability === "Both";
  }

  if (context === "battle") {
    return potion.availability === "Battle" || potion.availability === "Both";
  }

  if (context === "mini") {
    return potion.availability === "Mini";
  }

  return false;
}
```

* Mini can be included in the helper for later use, but no Mini UI trigger should be implemented in this feature.
