River Mini Game Rules

* The player must cross a river using rocks.
* The player has 3 rows of rocks.
* Each row contains 3 rocks.
* The player must choose one rock in each row.
* The player wins if they choose a safe rock in all 3 rows.
* The player loses immediately if they choose an unsafe rock.
* The game ends immediately on an unsafe choice, no matter which row the player is on.

Safe Rock Rules

* Row 1:

  * 3 rocks total.
  * 2 rocks are safe.
  * 1 rock is unsafe.
* Row 2:

  * 3 rocks total.
  * 2 rocks are safe.
  * 1 rock is unsafe.
* Row 3:

  * 3 rocks total.
  * 1 rock is safe.
  * 2 rocks are unsafe.

Safe Rock Randomisation Requirement

* Safe rocks should be randomly selected when the River Mini Game starts.
* Safe rocks should stay fixed for that mini game attempt.
* They should not change after each click.
* They should not change after a re-render.
* They should only regenerate when a new River Mini Game starts.
* The player should not know which rocks are safe before clicking.

Suggested state shape:

```js id="dfx3x4"

  { row: 1, safeCount: 2, rocks: [...] },
  { row: 2, safeCount: 2, rocks: [...] },
  { row: 3, safeCount: 1, rocks: [...] }
];
```

* Only rocks in the current active row should be clickable.
* Previous rows should no longer be clickable after a safe choice.
* Future rows should not be clickable until reached.

* Clicking an unsafe rock should:

```txt id="wqhexg"
Assign Reward
```

* Japanese should use the existing translation:

```txt id="qu9b2b"
報酬を割り当てる
```

* The title should appear at the top of the modal.
* The new reward token box should appear underneath this title.

New Reward Token Area Requirement

* Remove the visible text:

```txt id="fhwr9q"
New Reward Token
```

* The new reward token should be shown in its own container/box under the `Assign Reward` title.
* The box should visually communicate that the player must move the token.
* While the token is still inside the box, the box should have a glowing animation.
* The glowing animation should stop once the token has been moved out.

Instruction Text Requirement

* Under the new reward token container, add this sentence:

```txt id="cp766j"
Place the token into your spells, token bag or discard it to continue
```

* Japanese:

```txt id="l86pgv"
続けるには、トークンを自分のスペルかトークンバッグに配置するか、破棄してください。
```

* This sentence replaces the old `New Reward Token` label.
* The sentence should use the correct language and font.
* It should remain visible while the player is assigning the reward token.
* It should help the player understand that the token must be placed before they can continue.

New Reward Token Box Active State

* While the new reward token has not been moved:

  * show the reward token inside the new reward token box.
  * apply a glowing animation to the box.
  * keep the box fully visible.
  * keep the confirm button disabled.
* The token should be draggable from this box into:

  * spell slots.
  * token bag.
  * trash/discard area.

New Reward Token Box Disabled State

* When the token is taken out of the new reward token box:

  * keep the box visible.
  * disable the box.
  * make the box slightly transparent.
  * stop the glow animation.
  * do not collapse or remove the box.
* The page layout should not jump when the token is moved.
* The box should keep a stable height and width.
* The text showing where the token has moved should still be present.
* The player should be able to clearly see that the reward token has already been moved.

Moved Token Status Requirement

* Keep the existing status text that shows where the token has moved.
* This should still appear after the token is placed.
* Examples:

  * placed in token bag.
  * placed in spell slot.
  * placed in discard/trash.
* Use existing English/Japanese translations for those status messages.
* Ensure this text uses modal text colour and correct language font.

Confirm Button Requirement

* The Confirm button should always be visible.
* It should be disabled until the token has been placed in an appropriate place.
* It should become enabled once the reward token is placed into:

  * a valid spell slot.
  * the token bag.
  * trash/discard.
* The Confirm button should have:

```css id="j4t9sc"
margin-top: 30px;
```

* The Confirm button should use the global Button component.
* The Confirm button should use existing English/Japanese text:

  * `Confirm`
  * `確定`

Confirm Button Behaviour

* Clicking Confirm before the token has been placed should not be possible.
* Once enabled, clicking Confirm should commit the selected placement.
* Existing reward assignment logic should remain unchanged.
* Confirm should not become enabled if the token is still in the new reward token box.

Generic Component Requirement

* The component should not visually depend on where the token reward came from.
* It should work the same for:

  * battle rewards.
  * Cave Game rewards.
  * future mini game rewards.
  * future reward sources.
* Source-specific reward logic can still be passed in through props or route state.
* Visual layout should remain generic.

Cave Game Requirement

* Cave Game token rewards should continue to use this shared component.
* Because of this feature, Cave Game token assignment should now use the generic night sky background.
* Do not use the cave background for this assignment flow.

Battle Reward Requirement

* Battle token rewards should also use this redesigned assignment component.
* The assignment screen should use the same generic night sky background.
* Do not preserve battle-specific background styling for this component unless a later feature explicitly asks for that.

No `ul` / `li` Requirement

* Preserve the global UI rule from Bug-007.
* Do not use `ul` or `li` elements in this component.
* Use `div` elements with CSS grid or flex layouts.
* This applies to:

  * spell slot displays.
  * token bag contents.
  * trash section.
  * reward token box.
  * any placement/status lists.
