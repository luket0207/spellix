Feature-002: Implement Ice Beam battle potion behaviour

Status

* done

Related Feature

* EPIC-012 Feature-001: Add potion trigger UI and confirmation flow for Board and Battle potions
* EPIC-012 Feature-002: Add one-potion-per-turn limits and Active Potion gameplay section
* EPIC-006 Feature-002: Add dice-driven battle turns

Goal

* Implement the behaviour of the battle potion `Ice Beam`.
* When used in battle, Ice Beam immediately freezes the opponent.
* Frozen should behave exactly the same as it does from existing freeze effects.
* The opponent should receive the usual frozen animation.
* If Ice Beam has already frozen the opponent this turn, a rolled freeze token should not be consumed for doing nothing.

Behaviour Summary

```txt id="hr7as6"
Ice Beam: immediately freeze your opponent.
```

Trigger Requirement

* Ice Beam is a Battle potion.
* It should be triggered from the battle potion section using the existing Use button and potion confirmation modal.
* After the player confirms use:

  * remove Ice Beam from the player’s potion slots.
  * mark the battle potion use for this battle turn.
  * immediately apply frozen status to the opponent.
  * show the normal frozen animation on the opponent.

Frozen Status Requirement

* Ice Beam should apply the same frozen status used by existing freeze mechanics.
* Frozen should last until:

  * the opponent ends their turn.
  * or the opponent successfully rolls to remove it, if that is already how frozen behaviour works.
* Do not create a separate Ice Beam-only frozen state if the existing frozen state can be reused.

Frozen Animation Requirement

* The opponent should have the usual frozen animation applied.
* Use the same visual effect that already happens when a freeze token freezes an opponent.
* Do not create a separate Ice Beam animation unless technically necessary.

Freeze Token Non-Consumption Requirement

* If the player uses Ice Beam and then rolls a column that would also freeze the opponent, the freeze token should not be used up on that turn.
* The freeze token is technically doing nothing because the opponent is already frozen.
* Therefore, it should remain available for a future turn.

Example

```txt id="z9i6xd"
Player uses Ice Beam.
Opponent becomes frozen.

Player then rolls a column containing a freeze token.
The freeze token would normally freeze the opponent.
However, the opponent is already frozen because of Ice Beam.

Result:
The freeze token is not consumed.
```

Suggested Logic Direction

```js id="aqq9bw"
if (tokenEffect === "freeze") {
  if (target.isFrozen && battleTurnState.freezeAppliedByIceBeamThisTurn) {
    return {
      applyEffect: false,
      consumeToken: false
    };
  }

  return {
    applyEffect: true,
    consumeToken: true
  };
}
```

* Exact implementation can vary.
* The important requirement is that freeze tokens are not consumed when Ice Beam has already made their effect redundant.

Expected Behaviour

* Ice Beam appears in the battle potion section when owned.
* Ice Beam can be used during the player’s battle turn.
* Confirming Ice Beam consumes the potion.
* The opponent immediately becomes frozen.
* The usual frozen animation appears on the opponent.
* Frozen status behaves normally.
* If a freeze column is rolled later that same turn, the freeze token is not consumed if it would do nothing.
* Battle continues normally after Ice Beam is used.

Out Of Scope

* No changes to general frozen rules.
* No changes to freeze token power.
* No changes to battle dice logic.
* No new Ice Beam-specific animation.
* No unrelated battle UI redesign.

Testing Checkpoints

* Confirm Ice Beam appears in the battle potion section.
* Use Ice Beam.
* Confirm the potion confirmation modal appears.
* Confirm choosing No does not consume Ice Beam.
* Confirm choosing Yes consumes Ice Beam.
* Confirm the opponent immediately becomes frozen.
* Confirm the usual frozen animation appears.
* Confirm the opponent’s frozen behaviour works normally.
* Use Ice Beam, then roll a freeze-token column.
* Confirm the freeze token is not consumed if the opponent is already frozen by Ice Beam.
* Confirm freeze tokens still consume normally when they actually apply frozen status.
* Confirm battle potion one-use-per-turn rules still apply.
* Confirm there are no console errors.
* Update `testing.txt` before marking this feature done.

Completion Notes

* Reused the existing Battle potion list, potion confirmation modal, potion consumption path, `enemyFrozen` state, freeze checks, and snowflake overlay.
